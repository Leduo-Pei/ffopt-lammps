# FFOpt-LAMMPS Complete English User Manual

This manual is written for users who are developing molecular force-field
parameters for the first time. The intended workflow is simple: prepare LAMMPS
data files, experimental targets, and physically defensible parameter ranges;
edit one `ffopt.in`; then let FFOpt run Bayesian optimization (BO), focused
sampling, ANN surrogate training, active learning (AL), and final LAMMPS
validation. Interrupted calculations can resume automatically.

> **Alpha scope:** the current public release supports molecular crystals,
> isolated molecules, and molecular adsorption models. BTAH is the packaged
> regression system. Elemental, alloy, reactive-force-field, and general
> polymorph transfer workflows are not yet public support claims.
> The current adsorption backend treats one configured, uncharged metal atom
> type as a fixed substrate and optimizes only the molecular atom types.
> Charged, multicomponent, or optimizable substrates are outside the schema 1
> contract.

## 1. Understand the three file layers

A scientific project should remain small:

```text
my_project/
|-- ffopt.in                 # the only long-lived scientific input
|-- data/
|   |-- bulk/                # molecular-crystal bulk data
|   |-- molecule/            # isolated-molecule data
|   `-- adsorption/          # complex, slab, and molecule adsorption data
`-- runs/                    # generated by FFOpt; do not edit manually
```

Machine paths and scheduler resources are stored once outside the project:

```text
~/.config/ffopt/machines.toml
```

The same `ffopt.in` can therefore run on a workstation, one SLURM node, or
multiple nodes. Machine choice changes speed and concurrency only. It must not
change parameter bounds, candidate counts, random seeds, or the objective.

## 2. Install the environment

### 2.1 Recommended versions

- Python 3.11
- LAMMPS 22 Jul 2025, or a compatible version verified for this project
- OpenMPI, or the MPI implementation supported by the cluster
- CPU or CUDA PyTorch
- Linux with SLURM for production; Windows is suitable for development and GPU
  surrogate training

Do not install FFOpt into Conda `base`. A dedicated environment is easier to
upgrade, reproduce, remove, and restore.

### 2.2 Linux or cluster installation

The alpha release is distributed as a versioned GitHub Release wheel and is
not yet published on PyPI. Use the complete versioned URL below. Do not replace
it with an unverified `pip install ffopt-lammps` command.

```bash
conda create -n ffopt python=3.11 -y
conda activate ffopt
conda env config vars set PYTHONNOUSERSITE=1
conda deactivate
conda activate ffopt

conda install -c conda-forge "lammps=*=*openmpi*" openmpi -y
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu

python -m pip install \
  "ffopt-lammps[full] @ https://github.com/Leduo-Pei/ffopt-lammps/releases/download/v0.3.0a12/ffopt_lammps-0.3.0a12-py3-none-any.whl"
```

The example intentionally installs CPU PyTorch. On a GPU workstation, first
install the CUDA build recommended for the installed NVIDIA driver, then
install FFOpt. The `[full]` extra reuses an existing compatible PyTorch.

Verify that every executable comes from the intended environment:

```bash
which python
which ffopt
which lmp
which mpirun
ffopt --version
python -c "import site; print(site.ENABLE_USER_SITE)"
python -c "import ffopt, torch; print(ffopt.__version__); print(torch.__version__, torch.cuda.is_available())"
lmp -help | head
python -m pip check
```

`site.ENABLE_USER_SITE` should be `False`, preventing old packages under
`~/.local` from leaking into the new environment. Generated SLURM scripts also
set `PYTHONNOUSERSITE=1`. If `pip check` reports a missing package, install it
inside the active `ffopt` environment rather than relying on another
environment.

`torch.cuda.is_available()` returning `False` is normal in a CPU environment.
It means that NN and AL use the CPU. It is not an installation error.

When downloading a wheel or source archive manually, verify it against the
`SHA256SUMS.txt` file on the same GitHub Release page:

```bash
sha256sum -c SHA256SUMS.txt --ignore-missing
```

### 2.3 Windows installation

Run the following in Anaconda Prompt or PowerShell:

```powershell
conda create -n ffopt python=3.11 -y
conda activate ffopt
conda env config vars set PYTHONNOUSERSITE=1
conda deactivate
conda activate ffopt
python -m pip install "ffopt-lammps[full] @ https://github.com/Leduo-Pei/ffopt-lammps/releases/download/v0.3.0a12/ffopt_lammps-0.3.0a12-py3-none-any.whl"
```

LAMMPS and MPI may be installed separately. Their absolute paths are then
stored in a machine profile. Paths containing spaces are valid but must be
quoted on the command line.

### 2.4 Developer installation

```bash
git clone https://github.com/Leduo-Pei/ffopt-lammps.git
cd ffopt-lammps
python -m pip install -e ".[full,dev]"
python -m pytest -q
```

Normal users should install a fixed release or tag. Editable `-e` installation
is for developers.

The base package supports data inspection, input compilation, and
validation-only LAMMPS runs. The complete
`bo sample nn al audit finalize validate` workflow requires `[full]`.
`[saasbo]` and `[xgboost]` each include their complete optional runtime
dependencies.

### 2.5 Upgrade, reinstall, and uninstall

Upgrade to an explicit release instead of tracking the changing `main`
branch. Record `ffopt --version` and allow running jobs to finish before
changing the environment. The cleanest reinstall is to recreate the Conda
environment:

```bash
conda deactivate
conda env remove -n ffopt -y
conda create -n ffopt python=3.11 -y
conda activate ffopt
# Repeat Section 2.2 to install LAMMPS, MPI, PyTorch, and FFOpt.
```

Removing the environment does not remove user projects, `runs/`, or
`~/.config/ffopt/machines.toml`. To reset machine discovery, back up the
configuration first:

```bash
cp -a "$HOME/.config/ffopt" "$HOME/.config/ffopt.backup"
```

After reinstalling, verify `python`, `ffopt`, `lmp`, and `mpirun`, then rerun
`machine test` and `self-test`. Never delete an environment that is still used
by active SLURM jobs.

## 3. Configure a machine

### 3.1 Probe the current host and scheduler

```bash
ffopt machine probe
ffopt machine probe --partition YOUR_PARTITION
```

Probe is read-only. It reports Python, LAMMPS, MPI, CPU, GPU, and visible SLURM
partitions, then prints conservative suggestions. Replace `YOUR_PARTITION`
with a **SLURM partition name** shown by `sinfo`, not a compute-node name. If
you are unsure, run the first command without `--partition`.

Only `local` has a built-in zero-configuration profile. A cluster requires a
named profile created with `machine configure`; there is no hidden generic
`cluster` profile. Profile names must start with a letter and may contain only
letters, digits, dots, underscores, and hyphens, for example `mag1-2node`.

### 3.2 Local workstation

If `lmp` is already on `PATH`, the built-in serial profile can run directly:

```bash
ffopt doctor ffopt.in --machine local
ffopt run ffopt.in --machine local
```

Here, `local` means **execute directly on the current host without a
scheduler**. On a cluster login node, it would run on the login node and is
therefore unsuitable for production. Production cluster jobs must use a named
SLURM profile.

The built-in profile deliberately uses one serial worker. To use explicit
paths or more workstation cores, create a named local profile:

```bash
ffopt machine configure \
  --name local-workstation \
  --backend local \
  --lammps /absolute/path/to/lmp \
  --mpi /absolute/path/to/mpirun \
  --mpi-flavor openmpi \
  --workers 4 \
  --mpi-ranks 4 \
  --omp-threads 1 \
  --timeout 21600 \
  --force
```

### 3.3 One-node SLURM profile

The following example assumes 48 CPU cores per node:

```bash
ffopt machine configure \
  --name cluster-1node \
  --backend slurm \
  --lammps /absolute/path/to/lmp \
  --mpi /absolute/path/to/mpirun \
  --mpi-flavor openmpi \
  --partition YOUR_PARTITION \
  --nodes 1 \
  --total-cores 48 \
  --workers 12 \
  --mpi-ranks 4 \
  --omp-threads 1 \
  --memory-per-node 64G \
  --walltime 14-00:00:00 \
  --timeout 216000 \
  --force
```

### 3.4 Two-node SLURM profile

```bash
ffopt machine configure \
  --name cluster-2node \
  --backend slurm \
  --lammps /absolute/path/to/lmp \
  --mpi /absolute/path/to/mpirun \
  --mpi-flavor openmpi \
  --partition YOUR_PARTITION \
  --nodes 2 \
  --total-cores 96 \
  --workers 24 \
  --mpi-ranks 4 \
  --omp-threads 1 \
  --memory-per-node 64G \
  --walltime 14-00:00:00 \
  --timeout 216000 \
  --force
```

The CPU allocation must satisfy:

```text
minimum total cores = workers * mpi-ranks * omp-threads
```

- `workers`: independent parameter vectors evaluated concurrently.
- `mpi-ranks`: MPI processes used inside each LAMMPS evaluation.
- `omp-threads`: threads per MPI process, usually `1`.
- `total-cores`: total CPUs requested from SLURM.

`workers` changes speed, not the BO batch size. Scientific candidate counts
come from `ffopt.in`, such as BO `batch_size` and sample `points`.

Choose a realistic `walltime`. An unnecessarily long limit can reduce
backfilling opportunities on a shared cluster and leave a small test pending
with reason `Priority`. A 4 to 6 hour walltime is often suitable for machine
acceptance; use longer production limits only when needed.

The timeout for one LAMMPS parameter vector must be shorter than the SLURM
walltime. This lets FFOpt reject a pathological slow candidate, continue other
evaluations, and still write checkpoints. A 6 hour acceptance job can start
with `--timeout 7200`.

Running `machine configure` again without `--force` refuses to overwrite the
profile. With `--force`, only the profile with the same name is replaced;
other profiles are preserved.

The compact configuration saved in `~/.config/ffopt/machines.toml` resembles:

```toml
[machines.cluster-2node]
format = 2
backend = "slurm"

[machines.cluster-2node.lammps]
executable = "/absolute/path/to/lmp"
mpiexec = "/absolute/path/to/mpirun"
mpi_flavor = "openmpi"
timeout = 216000

[machines.cluster-2node.parallel]
workers = 24
mpi_ranks = 4
omp_threads = 1

[machines.cluster-2node.slurm]
partition = "YOUR_PARTITION"
nodes = 2
total_cores = 96
walltime = "14-00:00:00"
memory_per_node = "64G"
```

FFOpt expands stage resources at runtime. Older expanded profiles remain
readable; rerun `machine configure ... --force` to rewrite one in the compact
format.

### 3.5 Accept a machine before production

```bash
ffopt machine list
ffopt machine show --name cluster-1node
ffopt machine test --name cluster-1node
ffopt self-test --machine cluster-1node --watch
```

`machine test` submits a very small LAMMPS/MPI calculation and normally
finishes within minutes. A one-node profile tests one execution slot. A
multi-node profile starts its real distributed worker pool and verifies that
all requested nodes are used, exposing shared-filesystem, MPI, and resource
mapping problems before a scientific campaign.

`self-test` runs the real packaged BTAH NPT, BO, sampling, ANN, AL, audit, and
final validation workflow. It can take hours. It also runs the validation-only
adsorption module and checks the final objective, property errors, and
tolerances. Monitor it with `squeue`, `ffopt status`, and `ffopt logs` instead
of assuming that a long acceptance test is stuck.

## 4. Prepare LAMMPS data files

### 4.1 Supported sources

Data files may come from Materials Studio CAR/MDF converted by `msi2lmp`, or
from another topology builder. FFOpt does not depend on Materials Studio, but
the file must follow the LAMMPS data format and include topology, `Masses`,
`Pair Coeffs`, and `Atoms` information compatible with the selected templates.

`^M` shown by some editors is usually a Windows CRLF line ending. LAMMPS and
FFOpt normally read it correctly. It does not mean that the file is damaged.
Use `dos2unix file.data` only when normalization is needed, and do not modify a
production source file during a running campaign.

### 4.2 One parameter set per atom type

FFOpt assumes that all atoms of one LAMMPS type share one epsilon, sigma, and
charge. If the `Atoms` section assigns different charges to atoms of the same
type, split that type before fitting. One `type` line cannot represent several
different charges.

### 4.3 Data-file roles

- `bulk`: complete periodic molecular-crystal supercell.
- `single`: one isolated molecule with the same topology and type numbering.
- `complex`: adsorbed molecule plus substrate.
- `slab`: clean substrate matching the complex exactly.
- `molecule`: isolated adsorbate matching the complex exactly.

Recommended names are explicit:

```text
BTAH_bulk.data
BTAH_single.data
BTAH_Au111_complex.data
BTAH_Au111_slab.data
BTAH_Au111_molecule.data
```

Avoid ambiguous names such as `new.data`, `final2.data`, or `test-ok.data`.

Type labels must start with a letter and contain only letters, digits, and
underscores, for example `bhN1` or `C_aromatic_1`. Do not use spaces, slashes,
hyphens, or nonportable characters. FFOpt uses the labels to build parameter
and CSV column names and rejects unsafe labels before a run.

### 4.4 Inspect and cross-check data

The installed package includes the BTAH regression data:

```bash
ffopt inspect builtin:data/bulk/BTAH_822_bulk.data
ffopt data check \
  --bulk builtin:data/bulk/BTAH_822_bulk.data \
  --single builtin:data/molecule/BTAH_822_single.data \
  --strict
```

`builtin:` refers to a read-only resource inside the installed package. To
create a visible local copy of the complete BTAH acceptance project:

```bash
ffopt self-test --prepare-only --workdir ./ffopt-btah-example
cd ./ffopt-btah-example
ffopt inspect data/bulk/BTAH_822_bulk.data
ffopt data check \
  --bulk data/bulk/BTAH_822_bulk.data \
  --single data/molecule/BTAH_822_single.data \
  --strict
```

Path resolution rules are important:

- Ordinary relative paths passed to `ffopt inspect`, `ffopt data check`, and
  `ffopt init` are resolved from the current terminal directory shown by
  `pwd`.
- Relative paths inside `ffopt.in` are resolved from the directory containing
  that `ffopt.in`, regardless of the launch directory.
- Quote paths containing spaces. Confirm a path with `pwd` and `ls` before a
  production run.

For adsorption data:

```bash
ffopt data check \
  --complex BTAH_Au111_complex.data \
  --slab BTAH_Au111_slab.data \
  --molecule BTAH_Au111_molecule.data \
  --strict
```

`--strict` promotes warnings to failures and is recommended before production.

### 4.5 Naming quick reference

| Object | Recommended form | Restriction or meaning |
|---|---|---|
| `project` | `benzene_charge_only` | Start with a letter; use letters, digits, `.`, `_`, `-` |
| machine profile | `ccelab-2node` | Same portable rule as project names |
| type label | `C_aromatic_1` | Start with a letter; use letters, digits, `_` |
| data file | `benzene_bulk.data` | Include material and role; add facet or geometry if needed |
| run ID | `production_01` | Use letters, digits, `.`, `_`, `-` |
| parameter column | `C_aromatic_1_charge` | Generated from type label and parameter family; do not hand-write |

Paths may contain spaces or UTF-8 characters, but shell paths containing
spaces must be quoted. `ffopt init` quotes paths when needed. Do not encode
node counts, dates, or words such as `final` in scientific names. Machine
resources belong to profiles, timestamps and versions belong to provenance,
and final status belongs to validation.

## 5. Create a project automatically

This example creates a molecular-crystal project that optimizes charges only:

```bash
ffopt init btah_charge_only \
  --bulk-data builtin:data/bulk/BTAH_822_bulk.data \
  --single-data builtin:data/molecule/BTAH_822_single.data \
  --cells 8 2 2 \
  --mode charge_only \
  --target a=4.2422,1.0,A \
  --target b=17.8270,1.0,A \
  --target c=20.6850,1.0,A \
  --target alpha=72.63,0.5,degree \
  --target beta=87.15,0.5,degree \
  --target gamma=86.23,0.5,degree \
  --target density=1.3285,1.0,g/cm3 \
  --target sublimation=98.5,0.3,kJ/mol
```

Common modes are:

- `full`: optimize epsilon, sigma, and charge.
- `fix_sigma`: hold sigma fixed; optimize epsilon and charge.
- `charge_only`: hold epsilon and sigma fixed; optimize charge.
- `lj_only`: hold charge fixed; optimize epsilon and sigma.

`ffopt init` reads the initial parameters from the data file, writes an
explicit `type` table, and copies data into the standard project layout. It
cannot determine whether the numbers really came from CHARMM or whether a
range is physically sensible. Review every generated line.

The initializer writes `range charge delta 0.30` and `charge_limit 2.0` by
default. The first is a local `+/-0.30 e` window around each initial charge.
The second is an independent absolute safety bound for every final charge.
For a neutral organic molecule, the user may tighten the latter to `1.0` based
on physical judgment. These two limits are not interchangeable.

The complete target syntax is:

```text
NAME=VALUE[,WEIGHT[,UNIT[,TOLERANCE]]]
```

For example, `density=1.3285,1.0,g/cm3,0.03`. `weight` controls relative
importance in the objective. `tolerance` is an **absolute error gate** used by
final LAMMPS validation in the same unit as the target; it does not enter the
objective. Thus `a=4.2422,1.0,A,0.15` requires
`|a_calc - 4.2422| <= 0.15 A`. If omitted, `ffopt init` writes the current
default `max(3% of the absolute target, 1e-6)`. Review it against experimental
uncertainty and intended use.

## 6. Edit `ffopt.in`

### 6.1 Top-level statements

```text
ffopt 1
project btah_charge_only
workflow bo sample nn al audit finalize validate
```

- `ffopt 1` is the input schema version.
- `project` is only a project and result-directory name. It does not invoke
  BTAH-specific code.
- `workflow bo` runs BO only.
- `workflow validate` validates the initial parameters from the `type` lines.
- The full workflow runs BO, sampling, NN, AL, robust audit, finalization, and
  final validation.

A validate-only project needs no `range` statements because no search space is
built. If the workflow contains `bo`, every unfixed parameter needs either a
global range or a type-specific range.

### 6.2 Parameters and ranges

```text
parameters
    range epsilon factor 0.50 2.00
    range sigma   factor 0.85 1.15
    range charge  delta  0.30
    cutoff 8.0 A
    charge_limit 1.0
    neutrality derive bhN1
    mixing epsilon geometric
    mixing sigma geometric
    fix epsilon sigma

    # id label epsilon(kcal/mol) sigma(A) charge(e)
    type 1 bhN1 0.2000 3.2963 -0.6220
    type 2 bhHn 0.0474 0.3981  0.4760
end
```

- `factor 0.50 2.00` means 0.5 to 2.0 times the initial value.
- `delta 0.30` means the initial value plus or minus 0.30.
- `absolute LOW HIGH` supplies literal lower and upper bounds.
- `cutoff VALUE A` is the single global LJ cutoff shared by fitting and
  validation and must be explicit.
- `charge_limit 1.0` requires every final charge to satisfy `|q| <= 1.0 e`.
- `fix epsilon sigma` means that only charge is optimized.
- Omitting `fix` releases all three parameter families.
- `range type bhN1 charge delta 0.10` overrides the default range for one type.

`neutrality derive bhN1` removes that type charge from the independent search
coordinates and reconstructs it from type atom counts to enforce exact charge
neutrality. A charge-only molecule with 14 types is therefore commonly 13
dimensional. The reconstructed 14th charge still enters LAMMPS and the ANN
features.

The `cutoff` is part of the scientific force-field definition, not a property
runtime convenience. Bulk, surface, sublimation, adsorption, 0 K elasticity,
300 K promotion, and final validation all inherit the same cutoff. Changing it
changes the scientific fingerprint and requires a new campaign rather than an
old checkpoint.

For `material elemental` with `crystal bcc`, the input must satisfy
`cutoff >= 2.5 * sigma_max`, where `sigma_max` is the largest sigma allowed by
the complete optimization bounds, not merely the initial value. Every periodic
BCC model must also satisfy `cutoff <= 0.45 * h_min` after its configured
replication, where `h_min` is the shortest perpendicular cell height. If the
bounds conflict, increase replication instead of silently reducing the
cutoff. Generated force fields explicitly use
`pair_modify shift no tail no`.

### 6.3 Mixing rules

The current LAMMPS backend fixes epsilon to geometric mixing. Sigma may use
geometric or arithmetic mixing:

```text
mixing epsilon geometric
mixing sigma geometric
```

```text
epsilon_ij = sqrt(epsilon_i * epsilon_j)
sigma_ij = sqrt(sigma_i * sigma_j)          # geometric
sigma_ij = (sigma_i + sigma_j) / 2          # arithmetic
```

Use the rule defined by the original force field. Do not switch rules only to
obtain a lower objective.

### 6.4 Bulk properties

```text
property bulk
    data data/bulk/BTAH_bulk.data
    cells_in_data 8 2 2
    temperature 300 K
    pressure 1 atm
    equilibration 20000
    production 40000
    target a 4.2422 A weight 1.0 tolerance 0.15
    target density 1.3285 g/cm3 weight 1.0 tolerance 0.03
end
```

The standard bulk protocol is fixed: fixed-cell minimization, velocity
creation, fully flexible triclinic NPT equilibration, and NPT production
statistics. `cells_in_data` is the replication already present in the data
file; FFOpt does not replicate the supercell again.

Effective bulk settings are `temperature` (default `300 K`), `pressure`
(default `1 atm`), `timestep` (default `1 fs`), `equilibration` (default
`20000` steps), `production` (default `40000` steps), and velocity `seed`
(default `101`). Schema 1 does not expose a bulk protocol switch to NVT or
minimize-only. Production must contain at least the fixed statistical interval
of `5000` steps.

For elemental BCC elasticity, explicitly document the fit-quality gate,
static extrapolation drift gate, and separate strain windows:

```text
r2 0.98
static_drift 5 percent
static_strain  0.0005 0.001 0.002
dynamic_strain 0.002  0.004 0.006
```

Finite-temperature elemental BCC elasticity uses an adaptive promotion and an
independent validation protocol. The production Fe input first evaluates 38
cluster-balanced hard-gate candidates with seed 101. Exact one-seed 300 K
evidence reranks them; only 10 candidates receive seeds 202 and 303, and only a
complete three-seed candidate may win. This is 58 trajectories (`38 x 1 + 10 x
2`) inside one single-node finalist job. The winner alone receives the long
holdout validation seeds. `require_minimum yes` applies to the declared
`minimum 10` complete confirmation candidates.

`incumbent initial` is an explicit same-material version-iteration safeguard:
it protects the current `type`-line coordinate but re-evaluates every property.
Use `incumbent off` (the default) for a new material. FFOpt never searches old
`runs/` or `archive/` directories for an incumbent.

Each enabled elasticity fidelity must declare exactly one complete target
basis:

```text
# Single-crystal cubic basis
target static B       173.10 GPa
target static Cprime   48.00 GPa
target static C44     116.00 GPa

# Or user-facing isotropic basis
target static B       173.10 GPa
target static G        86.94 GPa
target static E       223.40 GPa
target static nu        0.2848 1
```

The supported bases are therefore exactly `B/Cprime/C44` and `B/G/E/nu`.
Do not mix the two bases or omit one member. Static and dynamic fidelities are
validated separately. The current Fe production input uses the isotropic
basis: its low-temperature static targets are `B=173.10 GPa`, `G=86.94 GPa`,
`E=223.40 GPa`, and `nu=0.2848`; its 300 K promotion targets are `B=170 GPa`,
`G=82 GPa`, `E=211 GPa`, and `nu=0.29`.
Negative `nu` is accepted for auxetic materials within `(-1, 0.5)`; zero is
excluded because ranking uses relative error. FFOpt reports the `E/nu` values
implied by each declared `B/G` pair and their closure mismatch, without
silently modifying or rejecting experimental values drawn from different
sources.

For either basis, exact LAMMPS structure and surface checks are hard gates, not
terms that a good elastic score can compensate. The Fe input requires lattice
errors within 1%, angle errors within 1 degree, density within 1%, and surface
energy within 5%. Born stability, stress-fit R2, and static extrapolation drift
are additional independent eligibility gates. Only eligible candidates are
ranked. For the selected elasticity basis, FFOpt first minimizes the largest
absolute relative target error (minimax), then the relative-error RMSE, then
the largest relative standard error of the mean across finite-temperature
seeds. Thus one excellent modulus cannot hide one poor modulus, and noisy
one-seed candidates cannot win over complete, repeatable evidence.
The broad first-seed triage cannot estimate SEM: it uses exact one-seed error
and the declared cluster/diversity reserve to choose the confirmation set.
SEM is applied only after all confirmation seeds finish, and only complete
multi-seed rows are eligible for publication.

The cubic evaluator always computes `C11`, `C12`, `Cprime`, and `C44` from the
hydrostatic, orthorhombic, and shear stress responses. When `B/G/E/nu` is the
declared target basis, `Cprime`, `C44`, and the Zener anisotropy remain reported
stability and interpretation diagnostics; they are not hidden optimization
targets. Two inner strain amplitudes are extrapolated with
`M(h) = M0 + q*h^2`; a third outer amplitude audits drift. Energy curvature is
diagnostic only because neighbor shells crossing a hard `lj/cut` boundary can
create discontinuous energy jumps even when a quadratic fit reports a high R2.
`r2` and `static_drift` are independent hard gates.

### 6.5 Sublimation enthalpy target

```text
property sublimation
    bulk data/bulk/BTAH_bulk.data
    single data/molecule/BTAH_single.data
    temperature 298.15 K
    target 98.5 kJ/mol weight 0.3 tolerance 5.0
end
```

The current estimator is:

```text
E_sub,estimate = E_single,min - <PE_bulk,NPT> / N_molecules
```

It uses a potential-energy difference as a controlled approximation to the
experimental finite-temperature sublimation enthalpy. It does not add ideal-
gas translation, rotation, vibration, pV, or standard-state thermal
corrections. Reports must retain this calculation definition. An experimental
sublimation enthalpy may still be used as a target, provided the approximation
is understood rather than described as a complete thermochemical free-energy
calculation.

The `temperature` in this block, default `298.15 K`, records the experimental
target temperature. The actual bulk simulation temperature is controlled by
the bulk property and defaults to `300 K`. Isolated-molecule minimization
inherits the global cutoff. The number of atoms per molecule is read from the
required single-molecule data file and is not supplied separately.

### 6.6 Adsorption

```text
property adsorption
    data complex data/adsorption/BTAH_Au111_complex.data
    data slab data/adsorption/BTAH_Au111_slab.data
    data molecule data/adsorption/BTAH_Au111_molecule.data
    protocol minimize
    metal Au
end
```

Without a `target`, adsorption energy is calculated only during final
validation and does not enter BO, ANN, or AL. Add a target only when a reliable
experimental value exists:

```text
target -3.5 kcal/mol weight 1.0 tolerance 0.5
```

The current adsorption protocol is deterministic 0 K minimization. In
addition to the three required paths and `protocol minimize`, only `metal`
(default `Au`) is configurable. Complex, slab, and molecule calculations all
inherit the global cutoff. Property-level cutoff, temperature, timestep, seed,
equilibration, and production keywords are rejected so that the input cannot
contain settings that silently do nothing.

`metal` must identify one fixed, zero-charge substrate type. Its LJ parameters
remain those stored in each data file. FFOpt updates only molecular types
shared by the complex and isolated molecule. Do not disguise a charged,
multicomponent, or optimizable substrate as one metal type to bypass this
constraint.

### 6.7 Objective function

The relative error for property `i` is:

```text
r_i = |calculated_i - target_i| / |target_i|
```

The total objective is the weighted relative root-mean-square error:

```text
J = sqrt(sum(w_i * r_i^2) / sum(w_i))
```

`weight` controls the relative contribution of each property. `tolerance` is
an independent absolute-error gate used only by final validation. Units are
validated strictly and are not silently converted. Use the documented units
such as `A`, `degree`, `g/cm3`, `kJ/mol`, and `kcal/mol`.

### 6.8 Bayesian optimization

```text
bo
    method auto
    initial_points 48
    batch_size 48
    max_rounds 200
    random_seed 42
    stability_audit on
    stability_top_k 20
    stability_seeds 101 202 303
    early_stop patience 30
end
```

BO is an **online LAMMPS loop**, not an offline model-training stage:

```text
BO proposes parameter vectors
        -> LAMMPS calculates the requested properties
        -> FFOpt computes the objective
        -> BO updates its search model and proposes the next batch
```

Consequently, BO must be connected to LAMMPS in a workflow diagram. The ANN
stage is different: it trains offline on LAMMPS-labelled data already produced
by BO and focused sampling and does not launch LAMMPS once per epoch.

- `method auto` selects GP, TuRBO, or SAASBO from the independent dimension.
  `ffopt explain` and `ffopt doctor` show the resolved method. If a high-
  dimensional task would use SAASBO but Pyro is unavailable, FFOpt warns and
  shows the TuRBO fallback.
- `initial_points` is the initial Latin hypercube design size. The complete
  initial parameter vector from the `type` table is evaluated once as an
  additional warm-start center, so `initial_points 48` produces 49 initial
  LAMMPS evaluations.
- `batch_size` is the scientific candidate count per BO round. It is not the
  same as machine `workers`.
- `max_rounds` is the maximum number of adaptive rounds.
- `patience` stops after the specified number of consecutive rounds without
  the minimum required improvement.
- The BO stability audit reevaluates strong candidates under independent
  velocity seeds to reduce the risk of accepting an accidental low objective.
- `stability_top_k 20` and three seeds permit up to `20 * 3 = 60` additional
  LAMMPS evaluations. This is an audit budget, not an NN truncation percentage.

`ffopt explain` prints the LHS count, warm-start count, initial total, full BO
search budget, stability-audit ceiling, and total BO ceiling separately. This
prevents machine concurrency from being mistaken for scientific sample count.

Advanced noise settings are `stability_max_objective_std`,
`stability_max_property_rel_std`, `stability_noise_penalty`, and
`stability_failure_penalty`, with defaults `0.05`, `0.05`, `1.0`, and `10.0`.
Do not change them without noise evidence for the new material.

### 6.9 Focused sampling

```text
sample
    points 2000
    centers 24
    center_selection diverse
    radii 0.01 0.025 0.05
    boundary_fraction 0.20
    global_fraction 0.10
    seeds 101 202 303
end
```

Focused sampling also launches real LAMMPS calculations. It creates an
explicit labelled training set rather than relying only on the adaptively
correlated BO history.

- `points` is the number of independent parameter vectors.
- Three `seeds` evaluate each vector three times, for `points * 3` LAMMPS
  evaluations.
- `centers` selects several centers from stable BO results.
- `radii` are normalized fractions of the full parameter bounds, not charge
  units.
- In material workflows, `boundary_fraction` samples around measured near-
  boundary centers; the remaining local quota uses strictly feasible centers.
  Empty center classes are explicitly reallocated and recorded in
  `metadata.json`.
- `global_fraction` adds points from the complete configured range.

Multiple local centers cover several stable basins. A global fraction helps
identify boundaries and failures, but excessive unstable wide-domain data can
reduce precision in the low-objective region.

### 6.10 ANN surrogate

```text
nn
    method ann
    ensemble 8
    hidden_layers 256 128 128 64
    epochs 1200
    batch_size 128
    learning_rate 0.0005
    validation_fraction 0.15
    test_fraction 0.10
end
```

`ensemble 8` trains eight independently initialized ANNs. Their mean is the
property prediction and their disagreement estimates epistemic uncertainty.
Training uses the previously generated LAMMPS-labelled table and is offline:
ANN epochs do not call LAMMPS.

The model learns, for one material and one topology, the mapping from the
independent parameter vector to LAMMPS-calculated properties. It is not a
transferable graph neural network across unrelated materials. Inspect held-out
R2, RMSE, residuals, and low-objective coverage for every property rather than
reporting only one aggregate R2.

### 6.11 Active learning

```text
al
    acquisition uncertainty
    rounds 2
    candidates 20
    candidate_pool 16384
    sampling_domain core_envelope
end
```

Each AL round uses the surrogate to screen a large candidate pool. Only the
selected candidates are sent to LAMMPS. Their new physical labels are appended
to the data set and the surrogate is retrained. Improvement is judged from
LAMMPS objectives, never from ANN predictions alone.

Elemental constrained AL evaluates every structure and surface gate
independently. If one gate surrogate is unreliable, FFOpt records the affected
constraint and enters `partial_constraint_fallback`: reliable gate
probabilities are retained, unreliable gates receive a conservative empirical
pass-rate estimate, and a reliable mechanical expected-improvement model still
guides proposals. It falls back to pure coverage only when reliable mechanical
guidance is also unavailable. This surrogate fallback never relaxes scientific
acceptance: exact LAMMPS structure/surface gates are still applied before a
candidate can receive a static or dynamic elasticity label.

The complete relationship is therefore:

```text
BO <-> LAMMPS                    adaptive physical search
focused sampling -> LAMMPS      deliberate training-data generation
ANN                              offline learning from stored labels
AL -> selected candidates -> LAMMPS -> append labels -> retrain ANN
```

### 6.12 Robust audit and finalization

```text
audit
    top_k 8
    seeds 101 202 303
end
```

Audit selects the best distinct candidates accumulated through AL and repeats
each with all configured LAMMPS seeds. The example performs `8 * 3 = 24`
evaluations and ranks candidates by `mean objective + objective standard
deviation`. Failed replicates remain visible in the replicate table.

The BO stability audit and final audit have different roles. The BO audit
selects repeatable centers for focused sampling. The final audit evaluates the
best post-AL candidates and decides which force field can be delivered.
`finalize` has no separate block. It resolves fixed parameters and the
neutrality-derived charge, then exports the complete atom-type table.

### 6.13 Final validation

```text
validate
    require_tolerances yes
    objective_max 0.03
    max_error_percent 3.0
end
```

The three gates are independent:

1. total weighted objective;
2. largest relative property error;
3. absolute tolerance for every target property.

Final validation always saves property and parameter tables, logs, final
structures, and relevant trajectories. No additional trajectory switch is
required. Do not copy BTAH thresholds to a new material without scientific
justification; derive them from experimental uncertainty and intended use.

## 7. Run four preflight checks

```bash
cd my_project
ffopt check ffopt.in
ffopt explain ffopt.in
ffopt doctor ffopt.in --machine cluster-1node
ffopt run ffopt.in --machine cluster-1node --dry-run
```

Confirm all of the following:

1. The independent dimension matches expectation.
2. Fixed, free, and neutrality-derived parameters are correct.
3. Fitted properties are not confused with validation-only properties.
4. Data paths, LAMMPS, MPI, PyTorch, and SLURM are all reported as valid.
5. The dry-run stage order matches `workflow`.

`doctor` checks more than path existence. It cross-checks all enabled bulk,
single, complex, slab, and molecule files for atom style, type labels, masses,
initial LJ values, and charge contracts. Normal input errors show concise
causes. Use `ffopt --debug doctor ...` or `ffopt --debug run ...` only when a
full internal traceback is needed.

## 8. Run and resume automatically

Direct workstation execution:

```bash
ffopt run ffopt.in --machine local-workstation
```

SLURM submission with monitoring:

```bash
ffopt run ffopt.in --machine cluster-1node --watch
```

After a walltime kill, SSH disconnect, or node failure, run the exact same
command again:

```bash
ffopt run ffopt.in --machine cluster-1node --watch
```

The default `.in` pipeline reads `state.sqlite`, scheduler state, checkpoints,
and required artifacts, then resumes from the first incomplete stage. Do not
use `--new` for resume; `--new` explicitly starts an independent campaign.

Once a run contains stage records, resume it with the same FFOpt version. A
version mismatch is rejected to prevent mixed provenance. Restore the original
version or intentionally start over with `--new`.

If `squeue` or `sacct` is temporarily unavailable or has not yet indexed a new
job ID, FFOpt keeps the stage in a waiting state and does not duplicate an
expensive submission. If all required artifacts already validate, the stage is
completed directly. Only an explicit terminal scheduler state enters failure
recovery.

Stop temporarily after BO:

```bash
ffopt run ffopt.in --machine cluster-1node --until bo --watch
```

Continue later from sampling:

```bash
ffopt run ffopt.in --machine cluster-1node --from-stage sample --watch
```

For a permanently BO-only project, write `workflow bo` directly.


## 10. Compare one-node and two-node execution

Use exactly the same `ffopt.in`, FFOpt version, and random seeds. Run separate
acceptance projects with the two profiles:

```bash
ffopt self-test --machine cluster-1node \
  --workdir "$HOME/ffopt-acceptance/one-node" --watch

ffopt self-test --machine cluster-2node \
  --workdir "$HOME/ffopt-acceptance/two-node" --watch
```

Compare the following:

- Both final validations must pass.
- BO batch size, initial points, sample points, and seeds must be identical.
- Final properties and objectives should agree within normal stochastic
  simulation variation.
- Two nodes should primarily reduce wall time for parallel BO, sampling, and
  AL LAMMPS evaluations.
- If the scientific budget changes with node count, the configuration or
  software is wrong. More nodes do not make the force field more accurate.

## 11. Troubleshooting

### `torch.cuda.is_available()` is `False`

This is normal for CPU PyTorch. A CPU profile can run the complete workflow.
Use a separate CUDA environment when GPU training is needed; do not modify
Conda `base`.

### Does `^M` break LAMMPS?

It is normally only the visible form of CRLF line endings. Run `ffopt inspect`
and a small `lmp -in ...` validation. If parsing succeeds, do not rewrite a
production file only for appearance.

### `DependencyNeverSatisfied`

A predecessor SLURM job failed, was cancelled, or never satisfied its
dependency, so the dependent job will not start. The pipeline runner does not
require users to maintain a handwritten `afterok` chain. Repeat
`ffopt run ... --watch`; FFOpt verifies stage artifacts and resubmits only the
incomplete stage.

### A job remains `PD`

- `Resources`: enough nodes, CPUs, or memory are not currently available; the
  job may start after resources are released.
- `Priority`: the job is waiting for scheduler priority or a backfill window.
- `QOSMaxCpuPerJobLimit`: `--total-cores` exceeds the QOS per-job CPU limit and
  will not resolve by waiting.

For the QOS case, reduce nodes, workers, and total cores in the named profile,
or request an appropriate QOS, then rerun `machine configure --force`.
Changing machine concurrency does not change BO or sampling budgets in
`ffopt.in`.

### BO objective is good but ANN R2 is low

BO data are adaptively correlated and need not cover a smooth mapping. The
stable sample count may be too small, a property may have too little dynamic
range, or seed noise may exceed the parameter response. Add stable multicenter
focused sampling before increasing network depth.

### Global R2 is poor but local R2 is good

The LAMMPS response may be learnable only inside stable local basins, while the
wide domain contains phase changes and failure boundaries. ANN cannot infer an
unsampled stable global relationship and should not be trusted to extrapolate.
Expand in layers, preserve the high-accuracy local model, and record boundary
and failure labels explicitly.

### A fixed-parameter model cannot lower the objective

A surrogate can accurately learn a mapping that cannot reach the experimental
targets. Limited force-field expressiveness affects the best achievable
objective but does not automatically imply poor R2. Diagnose data volume,
noise, target variance, coverage, and model error separately from physical
reachability.

## 12. Release and publication archive checklist

Preserve all of the following:

1. Original data files and how they were generated.
2. Final `ffopt.in`.
3. Complete selected pipeline directory.
4. FFOpt, LAMMPS, Python, PyTorch, and MPI versions.
5. The used `machines.toml` profile after removing private site information.
6. BO, sampling, ANN, AL, audit, and final validation tables.
7. Final parameters, structures, and trajectories.
8. Experimental target sources, units, temperatures, and uncertainties.
9. The sublimation-enthalpy approximation and omitted thermal corrections.
10. Scientific reasons for ranges, fixed parameters, and manual exclusions.

Do not edit generated CSV files and then continue a run. Do not preserve only
screenshots while discarding machine-readable results.
